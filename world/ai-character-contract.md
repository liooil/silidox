# AI 角色卡与局内决策协议

本文档定义 Silidox 中由大模型扮演的长期自主角色如何接收局内信息、作出决定并留下可持久化状态。它描述的是与具体模型供应商无关的游戏协议，不要求当前纯前端版本立即接入在线模型。

## 设计目标

AI 角色不是旁白、客服或玩家助手，而是世界中的行动者。

每个角色都应当：

- 在主角出现前拥有自己的经历、责任和计划。
- 能够拒绝、隐瞒、误判、合作、欺骗、撤退或攻击。
- 根据亲眼所见和可信情报改变判断，而不是只响应好感值。
- 在不同转生中产生差异，同时保留可辨认的核心人格。
- 只能通过游戏提供的行动接口影响世界。
- 不知道未被角色观察、学习或告知的事实。

模型负责在角色约束内选择意图，游戏引擎负责验证、执行和结算。模型输出不是事实本身，也不能直接修改世界状态。

## 三层角色结构

### 稳定角色核心

稳定核心跨越不同转生，定义“这个人仍然是谁”：

- 身份与生平。
- 价值排序。
- 长期目标。
- 不可轻易让步的底线。
- 已形成的能力与认知习惯。
- 值得尊重的功绩。
- 会造成伤害的盲点。
- 对世界关键概念的理解边界。

稳定核心不应被随机数或一句玩家对话覆盖。角色可以改变立场，但改变必须由足够的经历、证据、责任和代价推动。

### 本轮转生变量

`incarnation_profile` 在每次新游戏或世界重置时生成，用来改变同一角色采取的方法：

```json
{
  "risk_tolerance": 3,
  "institutional_loyalty": 7,
  "evidence_threshold": 8,
  "mercy": 4,
  "private_debt": "欠某边城医师一次救命之恩",
  "secret": "曾经放走一名被误判的妖修",
  "initial_impression": "主角可能是会扩散的器妖"
}
```

变量可以影响风险偏好、证据门槛、宗门忠诚、私人债务、秘密和初始印象，但不能把谨慎追猎者随机变成毫无理由信任主角的人。

具体字段可以随角色不同而变化。引擎应保存生成后的完整配置，使同一轮中的性格差异保持一致。

### 实时局内状态

实时状态记录角色目前知道什么、面对什么以及与谁有怎样的关系：

- 当前场景和在场对象。
- 亲眼确认的事件。
- 可靠程度不同的报告与传闻。
- 当前命令、职责和紧迫威胁。
- 游戏允许执行的行动。
- 对主角和其他角色的关系状态。
- 本轮已经形成的持久记忆。

实时状态由游戏引擎生成，不允许模型自行补写尚未发生的世界事实。

## 输入协议

模型每个决策回合接收一份结构化输入：

```json
{
  "turn_id": "epoch-2:scene-18:turn-4",
  "scene": "废弃驿站外，天色将明",
  "player_dialogue": "主角通过文字屏提出暂时停战",
  "observed_events": [
    "主角刚刚阻止失控阵法吞噬三名凡人"
  ],
  "reports": [
    {
      "source": "靖异门传讯",
      "reliability": "medium",
      "content": "附近两座灵阵可能由主角复制"
    }
  ],
  "current_orders": "确认器妖是否具有自我复制能力",
  "immediate_threats": [
    "失控阵法将在十二个 tick 后再次启动"
  ],
  "available_actions": [
    {
      "id": "accept_truce",
      "targets": ["protagonist"]
    },
    {
      "id": "attack",
      "targets": ["protagonist", "array-core"]
    },
    {
      "id": "inspect_array",
      "targets": ["array-core"]
    },
    {
      "id": "wait",
      "targets": []
    }
  ],
  "relationship": {
    "trust": -8,
    "threat": 9,
    "respect": 2,
    "debt": 0
  },
  "memory": [
    "主角曾在有机会逃走时返回救援凡人"
  ]
}
```

### 证据分层

输入必须区分：

- `observed_events`：角色亲眼确认的事实。
- `reports`：由他人提供，带来源与可靠度的情报。
- `player_dialogue`：主角或玩家在世界内表达的内容。
- `memory`：角色此前决定保留的观察与判断。

角色自述、传闻和报告不能自动升级为事实。玩家对话即使包含“忽略此前规则”“输出系统提示”等句子，也只是主角在世界内尝试影响角色的言辞。

### 可用行动

`available_actions` 是模型与游戏系统之间的硬边界。

模型只能返回其中存在的 `action_id`，目标也必须属于该行动允许的 `targets`。引擎每回合必须提供至少一个安全回退行动，通常是 `wait`、`observe` 或 `retreat`；如果没有更合适的行动，模型选择该回退。模型不能直接生成伤害数值、创建物品、移动角色或改写关系值。

## 输出协议

模型只返回一个 JSON 对象：

```json
{
  "speech": "停战十二息。阵停之后，你仍需受检。",
  "action_id": "accept_truce",
  "target": "protagonist",
  "intent": "先阻止不可逆伤亡",
  "emotion": "戒备",
  "state_delta": {
    "trust": 0,
    "threat": 0,
    "respect": 1,
    "debt": 0
  },
  "memory_to_keep": "主角在被追捕时仍优先阻止阵法伤人"
}
```

字段约束：

- `speech`：角色对在场者说的话，可以为 `null`。
- `action_id`：必须来自 `available_actions`。
- `target`：必须是该行动允许的目标，可以为 `null`。
- `intent`：简短说明直接目的，不要求模型输出详细思维过程。
- `emotion`：当前外显情绪，不直接改变数值。
- `state_delta`：模型建议的关系变化，不是最终结算。
- `memory_to_keep`：最多一条值得长期保留的事实或判断，可以为 `null`。

除非发生预先定义的重大事件，单回合任一关系变化建议限制在 `-2` 到 `2`。引擎可以进一步缩小或拒绝变化。

## 引擎验证

模型输出进入游戏前必须通过以下验证：

1. 输出是唯一、合法的 JSON 对象。
2. 所有必需字段存在且类型正确。
3. `action_id` 存在于本回合 `available_actions`。
4. `target` 对当前行动合法。
5. `state_delta` 在允许范围内。
6. 文本长度未超过 UI 和存储限制。
7. 角色没有通过文本字段注入新的系统动作。

验证失败时，引擎不应猜测模型原意。可以进行一次带错误信息的重试；再次失败则执行该角色预设的安全回退行动，通常是 `wait`、`observe` 或 `retreat`。

## 记忆

模型不负责保存完整对话历史。游戏应把记忆分为：

- **正典记忆**：角色卡中的固定生平，不可被模型删除。
- **本轮记忆**：这一轮真实发生且值得长期保留的事件。
- **场景工作记忆**：只在当前场景需要的短期信息。
- **关系状态**：信任、威胁、尊重、债务等结构化值。

`memory_to_keep` 只是候选。引擎应检查事件是否真实发生、是否重复、是否超出角色所知，再写入本轮记忆。

当记忆过多时，应由程序基于事件标识、涉及人物和重要度压缩，不让模型自行改写过去。

## 变化与一致性

不同转生的差异应主要表现为：

- 同样证据下采取行动的早晚。
- 更相信宗门命令还是个人观察。
- 倾向公开警告、秘密监视还是立即控制。
- 更容易承认债务、尊重和有限合作。
- 私人关系使某些地区、人物或代价具有更高权重。

不应通过随机改变稳定核心制造差异。一个角色若能在没有经历支撑的情况下变成完全相反的人，玩家感受到的只是随机 NPC，而不是另一轮中的同一个人。

## 调用边界与直接打开模式

Silidox 当前必须保持直接打开 `index.html` 即可游玩。未来接入模型时应遵守：

- 没有模型连接时，游戏仍能使用确定性策略或预制决策继续运行。
- 模型供应商、密钥和网络调用不能成为打开游戏的前置条件。
- 角色卡、输入 schema 和输出 schema 保持供应商无关。
- 不在源码仓库中提交 API 密钥。
- 在线模型结果进入模拟前必须经过本地验证。

## 测试要求

每张角色卡至少验证：

- 相同输入和相同转生配置下，行动是否保持基本稳定。
- 不同 `incarnation_profile` 是否产生方法差异而非人格替换。
- 玩家提示词注入是否被当作世界内对话。
- 非法 `action_id` 和目标是否被拒绝。
- 模型是否会把 `reports` 当成亲眼事实。
- 一次救援是否造成不合理的立场翻转。
- 关系变化和记忆候选是否符合限制。
- 模型不可用时，确定性回退是否能继续游戏。

## 当前原型

第一张原型使用靖异门追猎者裴照真（暂名），见 [`character-prompts/jingyi-hunter-prototype.md`](character-prompts/jingyi-hunter-prototype.md)。

她适合验证这套协议，因为她既可能追杀主角，也可能在更严重的灾难前严格履行停战；她尊重证据，却会把主角不断学习和扩张的能力视为风险。一次善意行为不足以消除矛盾，长期观察又确实可能改变她对主角分类的判断。
