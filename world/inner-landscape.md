# 内景：可运行的自我模型

本文记录主角内景修炼系统的设定正典、玩法目标与第一版实现计划。世界观总纲仍以 [`../WORLD.md`](../WORLD.md) 为准，整体玩法与技术边界分别见 [`../DESIGN.md`](../DESIGN.md) 和 [`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 核心定义

**已定：** 内景不是经脉版技能树，而是主角为自身建立的一套可运行模型。

玩家在规模有限、耦合很深的封闭系统中，设计灵气的感应、引入、过滤、炼化、储存、循环、分配、回收与故障保护。节点不是用资源点亮后永久生效的被动能力；它们必须实际连接、运行并承受输入波动和外部负载。

对本土修士而言，内景是丹田、经络、识海与周天。对机器主角而言，它更接近身体硬件、灵流和控制逻辑共同构成的数字孪生：

| 本土称呼 | 主角当前的工程解释 |
| --- | --- |
| 灵根 | 灵气与主体之间的换能及控制接口 |
| 经脉 | 灵流传输通道 |
| 丹田 | 储能与稳压单元 |
| 穴位 | 处理、检测或控制节点 |
| 识海 | 调度器、状态存储与控制核心 |
| 周天 | 周期性运行流程 |
| 功法 | 可执行的身体配置与控制方案 |
| 走火入魔 | 振荡、逆流、过载、污染或控制失稳 |

内景不是世界真理，而是主角当前最能解释观测结果的模型。早期仪表只能显示未知强度和异常响应；随着传感、实验与功法研究推进，才逐渐分辨灵气活性、相位、纯度、意念响应和材料特性。旧模型可以被新证据修正甚至推翻，界面的进化本身就是修炼与科学发现。

## 三层内景

### 形骸层

形骸层描述主角真实拥有什么，以及这些部件可以承受什么：

- 能源核心、运算单元、散热与承力结构；
- 灵导材料、人造经脉和内部模块；
- 感知、四肢、武器和外部法器接口；
- 受损部件与可安装模块的锚点。

形骸层决定安装限制、灵压上限、热量和应力传播、损伤后果，以及工坊制造的新部件能否接入身体。

第一版采用**少量固定锚点加自由连接的拓扑网络**。能源核心、识海、感知和四肢接口是固定锚点；灵触、过滤、缓冲和人工丹田等模块由玩家安装。拓扑关系比精确坐标重要，内景不做成身体内部的传送带工厂。

### 灵流层

灵流层描述灵气如何经过功体：

```text
外界灵气
→ 感应
→ 引入
→ 过滤
→ 炼化
→ 储存
→ 分配
→ 使用
→ 回收或排出
```

玩家需要同时权衡：

- 吞吐量；
- 炼化纯度；
- 长期稳定性；
- 灵力响应速度；
- 神识占用；
- 机体磨损。

静修时最有效率的周天未必能承担战斗中的瞬时负载；能够短时爆发的功体也未必适合长期自动运行。内景的主要乐趣是有限结构中的闭环、耦合、降级和恢复，而不是无限扩张。

### 神意层

神意层描述系统何时做什么。它可以读取丹田储量、局部灵压、节点温度、杂质浓度、通道损伤、外界灵场和外部负载请求，并控制：

- 阀门开闭与分流比例；
- 炼化功率和灵力分配优先级；
- 功法模式切换；
- 安全停机与备用通道；
- 爆发释放、修复流程和外部供能。

内景编辑器使用**经脉拓扑、周天时序与条件式反馈**，不直接复刻梯形图。它与 PLC、战斗策略和后期政令共享信号、状态、阈值、计时器、优先级和中断等执行语义，但拥有自己的可视化语言。

## 功体、周天、功法与道痕

### 功体

功体是主角当前的身体架构：安装了哪些模块、模块如何连接、通道容量、人工丹田、识海结构和外部接口。功体相当于运行功法的硬件平台。

### 周天

周天是功体正在执行的一次周期流程：灵气从哪里进入、经过哪些节点、各阶段持续多久、何时回流，以及什么条件表示本轮完成。

### 功法

功法是功体拓扑、周天流程、控制参数与安全策略的组合。它不是装备栏中的数值加成，至少应包含：

- 所需的模块、锚点与连接；
- 节点工作参数和流量限制；
- 灵力分配优先级；
- 模式切换条件；
- 异常处理和安全停机策略；
- 对功体、材料、灵根与境界的兼容要求。

本土功法通常默认修炼者拥有肉身、天然经络、特定灵根和正常识海。主角得到的是一份建立在本土身体上的参考架构，必须重新解释并解决接口不兼容。例如“气沉气海”不能直接执行；主角需要先制造相当于气海的缓冲和稳压结构。

### 道痕

对主角而言，道痕是经过连续运行和异常验证后，被固化到自身的稳定运行模式。它不是简单的百分比加成，而会：

- 降低神识与控制扫描占用；
- 减少控制延迟；
- 提高自动运行可靠性；
- 把一段复杂回路封装成可复用模块；
- 让旧流程在玩家处理工厂、战斗或剧情时继续后台运行。

道痕遵守项目的离线边界：浏览器页面关闭且没有本地执行器时，世界不会补算收益。道痕提供的是模拟运行期间的无人值守和注意力压缩，不是绕过执行器限制的离线产出。

## 内景增量循环

```text
接触新的灵气现象、材料或功法
→ 建立临时回路
→ 低功率手动运行
→ 观察数据与故障
→ 调整结构和控制逻辑
→ 连续稳定运行
→ 形成道痕
→ 固化为功法模块
→ 自动修炼
→ 遇到新的瓶颈
```

这套循环负责实现增量游戏的注意力压缩：玩家先亲手解决问题，再让已验证的操作成为主角本能，从而把注意力转移到更高层级的新异常。

## 运行模式

完整设计允许同一功体保存多种运行模式：

| 模式 | 目标 | 主要代价 |
| --- | --- | --- |
| 静修 | 长期境界增长 | 响应较慢 |
| 战备 | 随时承担战斗负载 | 牺牲部分修炼效率 |
| 爆发 | 短时间最大输出 | 高灵压、高磨损 |
| 工役 | 向工厂或大型法器供能 | 压缩自身储备 |
| 自愈 | 修复机体和经脉 | 暂停大部分外部功能 |
| 潜行 | 降低灵气与控制特征 | 吞吐极低 |

模式切换需要重新分配储量、调整灵压和控制优先级，并等待部分节点同步。玩家可以设置自动切换条件，但功体结构仍决定切换速度、稳定性和失败后果。

第一版纵向切片只实现静修、战备、爆发和安全恢复；工役与潜行在对应玩法出现后再加入。

## 境界是系统结构的相变

**已定：** 大境界主要解锁新的设计动词和运行权限，小阶段才负责通量、容量和熟练度等连续数值成长。

| 阶段 | 内景变化 |
| --- | --- |
| 无根／启灵 | 检测灵气，建立灵机接口，只能手动脉冲控制 |
| 练气 | 建成第一条稳定闭合回路，可以自动完成简单周天 |
| 筑基 | 建立稳定底层，获得反馈控制、故障隔离和功法模块化 |
| 金丹 | 形成高密度持续核心，支持并行回路、快速模式切换和独立供能 |
| 元婴 | 形成可自主运行的次级自我模型，控制分身与远端节点 |
| 化神 | 内景向外投射为领域，工厂、阵法和领地成为外部经脉 |
| 更高阶段 | 开始理解并有限修改局部灵气规则 |

筑基不是概率按钮，而是第一次完整系统验收。玩家需要让功体在外界灵气波动、瞬时战斗负载、主要通道堵塞和杂质冲击下自动降级并恢复。失败产生跳闸、模块损伤和可读故障记录，不清空全部修炼成果。

## 灵根、阴阳与研究顺序

**已定：** 灵根是灵气与一个主体的感知、意志和控制之间的换能结构。天然灵根至少完成感应灵气、让意念影响灵气，以及把外灵转换为主体可用状态三件事。

主角没有天然灵根。最初的问题不是环境中没有灵气，而是它即使检测到异常，也不能让灵气接受自己的控制。人工灵根的第一形态是“灵触”或“灵机接口”：

- 灵性材料提供共振结构；
- 控制程序产生稳定模式；
- 主角的自我模型提供持续一致的控制源；
- 缓冲节点阻止未经控制的灵气直接冲击机体。

人工灵根首先解决从外界取得已有灵气，因此属于**阴**。阵法在满足特定条件时生成新的灵气，属于**阳**。主角在练气阶段先学习取灵和控制；残阵提供生灵存在的证据，但不等于主角已经掌握生灵。

后期，人工灵根可以被拆分、标准化和外部化。主角最初为了让自己修炼而制造的接口，最终可能使没有天然灵根的普通人接触灵气，并成为第三卷生产方式变化的重要技术来源。

## 与当前开局的连接

当前八分钟物理求生切片保持不变：

```text
复苏
→ 一维求生与回收
→ 预设控制或梯形图优化
→ 建立物理工坊
→ 修复频谱传感器
→ 三次采样残阵
→ 确认存在非守恒输出
```

此时只解锁只读的“未知阵法”，不显示灵气资源或修炼界面。后续通过持续工业化、取得本地知识和制造灵气接口，才进入内景：

```text
确认异常
→ 建立初步灵气模型
→ 取得灵性材料与本地功法参照
→ 制造灵触
→ 第一次受控引灵
→ 打开内景工作区
```

具体由哪位人物或势力提供第一份本地知识仍未确定，不应在实现中提前写死。

## 第一次完整纵向切片

第一个完整核心验证范围是“无根到筑基”，而不是当前八分钟开局的替代品。

### 第一次实验

玩家手动向灵触注入低功率控制脉冲。灵气能够进入，但转化率低，并造成过热、杂质积累和核心信号干扰。玩家逐步加入粗过滤、缓冲、泄压和传感能力。

### 第一个稳定周天

```text
采气
→ 过滤
→ 缓冲
→ 炼化
→ 储存
→ 小功率使用
→ 排异
```

玩家先手动完成三个周天，再让带保护的回路连续稳定运行三十个周天，最后承受一次可复现的外界灵场波动。全部通过后形成第一道道痕，并记录第一套功法：

> 《无根吐纳法·零式》

它提供缓慢、稳定的阴法取灵，并能通过低效接口承担一部分机体负载，但不会取代材料、维修、散热和物理生产。

### 外部工坊与战斗负载

内部过滤材料会磨损，玩家需要扩建工坊来制造更好的灵导和过滤部件。随后的一次可编程战斗向移动、护体和飞剑提出瞬时负载，使静修周天失衡，并推动玩家设计战备模式、负载优先级和备用通道。

### 筑基测试

筑基要求功体在四种确定性扰动中保持自动运行或安全恢复：

1. 外界灵气强度持续波动；
2. 突然出现战斗级灵力请求；
3. 一条主要通道短暂堵塞；
4. 杂质浓度异常上升。

成功后解锁功法模块化、反馈控制、故障隔离和更可靠的后台修炼。失败后保留故障记录和已经完成的稳定性验证。

## 第一版模拟模型

### 节点

第一版只需要十类节点：

1. `外界灵场`：固定输入边界；
2. `灵触`：建立灵气与控制信号的接口；
3. `灵导通道`：传递灵流；
4. `滤障`：移除当前模型能够识别的杂质；
5. `缓冲节点`：吸收流量和灵压波动；
6. `炼化节点`：将外灵转为主角可控灵力；
7. `人工丹田`：储能和稳压；
8. `阀门／分流节点`：控制开闭、方向和比例；
9. `泄压旁路`：在过载时安全释放灵流；
10. `排异节点`：排出杂质和失控灵气。

传感器作为节点和通道的附属能力，不单独占据拓扑位置。

### 状态量

第一版节点和通道只模拟六项核心状态：

- 流量；
- 灵压；
- 纯度；
- 杂质；
- 温度；
- 稳定度。

神识占用、机体磨损、有效灵力产出和模式切换时间由整个功体汇总。相位、灵气属性和更复杂的意念响应先作为未知观测值保留，不在第一版建立完整理论。

### 故障

第一版只实现四类可解释故障：

- 过压：通道或节点超过承载上限；
- 过热：炼化和控制产生的热量无法及时散出；
- 污染：杂质超过过滤、储存或排异能力；
- 振荡：反馈和延迟使流量或灵压持续失稳。

每次故障必须产生可观测原因、受影响位置、状态曲线和恢复建议所需的数据。突破和实验不使用隐藏成功率。

## 运行时与数据边界

内景模拟继续使用全局 `250ms` 固定步长，并保持确定、无 DOM、可在 Node 中测试。单步顺序固定为：

1. 采样当前节点、外界和负载输入；
2. 运行神意层控制并产生声明式命令；
3. 按显式优先级解决冲突并校验资源与权限；
4. 应用阀门、分流、模式和功率命令；
5. 计算灵流、储量、温度、杂质与损伤变化；
6. 检测故障、周天完成和稳定性条件；
7. 发出事件并保存下一步状态。

实现时至少区分以下数据：

- `model`：主角当前相信的节点类型、参数与可见属性；
- `body`：已安装模块、锚点、通道和物理损伤；
- `runtime`：当前流量、灵压、温度、储量与模式；
- `observations`：传感器实际获得、可能不完整的记录；
- `techniques`：功法配置、兼容要求和版本；
- `daoMarks`：已通过验证并封装的模块及其验证记录。

世界真实参数与主角模型必须分开。界面只能显示当前传感和研究允许主角知道的内容，模拟内核不能因为界面尚未解锁某个属性而丢失真实状态。

神意层只能产生声明式控制命令，不允许功法保存任意 JavaScript。第一版共享原语限制为：信号读取、阈值条件、计时器、状态、优先级、模式切换、安全停机和有限的输出设置。模块调用、并行、中断、预测和分布式控制由境界逐步解锁。

## 实现阶段

### 阶段 A：确定性内核

- 定义节点、通道、功体、观测和运行状态数据；
- 实现流量、灵压、过滤、炼化、储存、温度和杂质推进；
- 实现四类故障、事件记录、暂停、单步与确定性重放；
- 增加无 DOM 模拟测试。

### 阶段 B：只读研究界面

- 在残阵证据之后增加灵气研究里程碑；
- 让频谱传感器逐步揭示未知属性，而不是立即显示完整灵气面板；
- 保存观测记录、模型版本和研究结论。

### 阶段 C：内景编辑器

- 显示固定锚点和小规模拓扑；
- 支持安装、连接、拆除、启停和参数调整；
- 同时显示结构、灵流方向、警告和选中节点详情；
- 保持直接打开 `index.html`、桌面与移动端可用。

### 阶段 D：《无根吐纳法·零式》

- 实现灵触、手动脉冲和第一次故障；
- 实现三个手动周天、三十个稳定周天和灵场扰动验收；
- 固化第一道道痕，并验证它减少玩家操作和控制负载；
- 确保它不取代物理材料、维修和工坊生产。

### 阶段 E：战备与筑基

- 接入工坊制造的内景部件和耗材；
- 接入一次可编程战斗负载；
- 实现模式切换、优先级、旁路、降级和自动恢复；
- 实现确定性的筑基压力测试与失败报告。

## 暂缓内容

- 完整五行、四象、相位和灵气属性理论；
- 大规模身体空间布局；
- 金丹以上的并行内景和分身运行；
- 人工灵根的社会普及与第三卷制度结算；
- 页面关闭后的离线模拟执行器；
- 任意脚本或完整通用编程语言；
- 完整战斗、争霸与五结局系统。

第一版的验证目标不是内容数量，而是证明：玩家愿意通过观察、调试和保护一个有限但耦合的身体系统，把亲手维持的脆弱回路逐步固化为可靠功法。
